# full-self-working

An autonomous freelance-outsourcing agent that runs on one local machine around the clock. It answers inquiries, sends quotes and proposals, keeps a price table current from live market samples, delivers the work, and moves its effort toward the service and platform pairs with the best hourly yield.

`main` is the v0 line since the takeover of 2026-10-26, recorded as the ledger event `takeover`; the 2c77326 line is kept on `archive/20261026-151909`. The scheduled supervisor runs from a detached worktree of `main` and hands over to a new `main` commit once its module graph imports, and `scripts/rollback-takeover.mjs` moving `main` back is the rollback.

- One branch: every unit commits and pushes on `main`, and the supervisor hands over to the new commit at its next tick once the code imports. A handover restarts the BrowserSkill daemon, which comes back by itself and reconnects the operator's Chrome while a Chrome window is open; `scripts/takeover-check.mjs --since handover` judges each move, and a push while `bsk browsers` lists no Chrome waits until it does.

## Commons boundary

fsw is a commons every operator runs, so the repository is generic and publishable and holds nothing about one operator, neither data nor presentation. Everything about one operator lives in `instance.local/` (profile, background, business registration, payout account, ledger, job workspaces, lessons, logs, surface recordings) and is ignored by `*.local*`; a page about one operator, such as a portfolio site or a brand, lives in that operator's own repository and reads their data there, so fsw renders and deploys no operator site (docs/DESIGN.md, Decisions). Code reads the instance through `src/core/instance.mjs`; examples with placeholders live in `examples/instance/`. A personal value never appears in tracked files, tests, fixtures or commit messages. `npm run check:privacy` fails on any tracked file that matches a value from the instance, and skips when there is no instance, so in a worktree without one it runs with `FSW_INSTANCE` pointing at the operator's instance.

Learning splits on the same line, the way a personal agent keeps its memory apart from its code. What one operator's deals teach (customer cases, quote outcomes, the price table, the lessons and playbook drawn from them, logins, secrets, settings) is that operator's memory layer and stays in the instance. What holds for every operator (how a platform's pages behave, what its notices mean, a failure mode of a send, a market fact) is the commons' moat: it lands in the repository as code with a test, a descriptor field or a `docs/NEGATIVE-CORPUS.md` row, never as an instance lesson only one machine reads. Every customer act a platform shows (a reply, an open, a hire, the customer leaving the chat, an unread refund) is recorded as an event the quote results read, so price learning and the value gate count it; an act fsw cannot classify yet is the next row to add, not a park.

## Layout

docs/DESIGN.md holds the module map and the contracts between modules.

- `src/core` holds the instance loader, the SQLite ledger (`node:sqlite`, migrations by user_version, v4 adds the outbox), the one-time approval import, log, notify and Seoul clock helpers.
- `src/platforms` holds one descriptor per marketplace (fees, payment model, contact and payment policy, pacing), validated on load, plus the shared kit.
- `src/surface` is the one interface over the platforms (`openSurface`): it maps the page-level code in `src/platforms/<id>` (extractors, parsers, the kmong conversation and listing halves) to Inbound, Thread and Receipt, refuses a write without the authorize verdict send, and records or replays every driver call; `src/browser/driver.mjs` drives the operator's signed-in Chrome.
- `src/policy` is the deterministic outbound gate and slop lint; every message, quote, proposal and listing passes it before it leaves the machine.
- `src/economics` holds the service catalog, fees, exchange rates, market summaries, sampling, pricing and the price table file, and the quote results that price learning, the allocation and the quote funnel read.
- `src/triage` decides each list row (wait, park, observe, open) from the row and the ledger alone; `src/policy/authorize.mjs` composes every send rule; `src/outbox` plans, screens, sends with read-back and resolves every outbound item; `src/deal` is the one state machine for jobs, quotes, payments and money events; `src/work` runs a paid job's recipe behind an executor seam and has accepted work reviewed by the other model family before the operator approves its delivery; `src/loop` is one platform step from sense to drain and the effects the deal returns.
- `src/brain` decides a reply and quote through the model, with every amount set by code; `src/portfolio` and `src/learning` keep the ranked portfolio, the outcome cases, the lessons and the playbook.
- `src/supervisor` is the daemon and its 13 jobs (the `run/state.json` lastRuns ids of the live tree), the hourly lead supply report and the 09:00 digest; `src/listings`, `src/projects` and `src/profile` are the kmong gig writer and watch, the enterprise proposals the drain sends, and the profile tools; `docs/LISTING-DESIGN.md` is the design record of the gig images.
- `bin/fsw.mjs` maps each verb to `src/cli`: init, profile, doctor, settings, status, tick, run, schedule, approve, deal, evidence, job, probe, market, price, listings, projects, services and edits. `src/core/config.schema.json` owns every config key; `fsw settings` changes one.
- `docs/NEGATIVE-CORPUS.md` lists what the 2c77326 tree learned, each lesson tied to the gate, test or note that holds it.

## Rules

- The service catalog (`src/economics/services.json`, mapped onto each platform's labels in its descriptor) is the current reach, never the limit: demand under a label no service covers is the queue of services to add, and each such label becomes a service with its recipe, price row and label mapping rather than a request left with the operator. Services enter in order of ease and proven return: first what the executor can deliver now in short cycles, until the return is proven (the founder's bar is about 1,000,000 KRW a month in spend returning 5,000,000 KRW) and delivery runs without the operator, then the harder fields such as music composition, 3D modeling, X commissions and VTuber work. A step that needs a resource only the operator holds, such as a Mac for an iOS build, asks him for it when the step comes instead of keeping the service out. The hourly lead supply report and the digest list the five labels with the most threads parked out of catalog over seven days as the candidates to add.
- A channel that brings no leads is first checked at the platform's own matching settings, since an unset one reads as missing demand; `fsw doctor` warns for each offered soomgo catalog service without request items, and the hourly lead supply report lists them.
- A blocked mechanism gets another mechanism before anyone proposes dropping what it served: a platform read that meets a bot wall moves to another engine, cadence or page in its descriptor and settings, and an operator-mandated source leaves only on the operator's word.
- A platform timestamp without a zone is read in the zone the page's own relative time confirms, checked live before its parser ships; soomgo request times are Seoul time although nothing in them says so.
- A live page is read from this tree only through `scripts/probe.mjs`, whose window keeps it off the live supervisor's polls; recordings with customer text stay under `instance.local/qa/surfaces`, and fixtures under `test/fixtures/surfaces` are synthetic.
- Platform rules are data in each descriptor and are enforced by `src/policy/gate.mjs`; a rule a script can decide is a gate, never prose in a prompt.
- Customer-facing copy passes the slop gate: no em dashes, no middle-dot enumerations, no invented metrics, no claims the instance profile cannot back.
- Every outbound customer item passes `src/outbox` and `authorize`: a `Surface` write method (`send`, `quote`, `payRequest`, `propose`) is called only from `src/outbox/drain.mjs`, and only `src/deal` writes job status, quote status, payments and money events. The seller's own pages are not customer items: the gig writer (`openListingSurface`, `src/listings/gig.mjs`) passes `checkListing` and the career write passes `careerStep`, and a forced observe pass skips both.
- Money moves only through the channel the platform allows. Contact details and payout accounts are released only where the descriptor permits.
- A paid quote on a buyer request goes out only when `judgeQuote` (`src/economics/quote-gate.mjs`) finds its expected value above zero at the share-blended win chance and `paceSpent` finds the day's pace allows it; a drop parks as "gate: ..." and is never a count cap.
- Every path a platform spends the operator's money on is read, including spend the platform makes by itself (automatic quote campaigns, auto-recharge), and reported beside fsw's own spend: the soomgo surface's `spend()` feeds the hourly supply report and the digest, and `platforms.<id>.platformSpendMaxPerDay` bounds the automatic budget.
- A portfolio item is public only after its payment is recorded and the client allowed portfolio use in a sentence of their own after the delivery; `src/loop/permission.mjs` and test/permission.test.mjs hold the check, and only the operator lifts a denial.
- Every operator choice is a setting: a mode, cap, answered service, budget, market engine or cadence, or a figure a listing prints is a key in the instance's `config.json` or `profile.json` with its type, default and meaning in `src/core/config.schema.json` (the example config is generated from it), never a constant one operator picked; `npm run check` (`scripts/check-example.mjs`) fails a key the code reads that the example lacks, and a figure a profile can answer, such as a career length, is derived from its dated roles.
- A live job is retired only by the founder in writing.
- Schedules start on round Seoul marks; each cron carries its Seoul time and reason.
- Module boundaries live in `scripts/check-imports.mjs`, part of `npm run check`: it fails a forbidden import between modules, a module with no row and a file-level import cycle, and a change that adds a module adds its row there and in docs/DESIGN.md.
- A choice between mechanisms (an executor, a store, a send path, a browser engine) lands in the Decisions section of `docs/DESIGN.md` with its reason and evidence in the change that makes it; the plans the build ran on live outside the repository.
- A lesson from a platform page, the market or a failure lands in `docs/NEGATIVE-CORPUS.md` with its holder; `scripts/check-negative-corpus.mjs` keeps every held row tied to a file that contains its anchor.
- README.md is for the person deciding whether and how to run fsw, and AGENTS.md for the agent changing it; `scripts/check-readme.mjs` (the re0-readme audit, part of `npm run check`) fails a README line written for an agent, such as a check command, and an AGENTS.md line written for a reader.
- Source files stay at or under 400 lines (`scripts/check-size.mjs`); a test file is listed and never fails it.
- Commands: `npm ci` once (ajv, for `fsw settings` only), `npm test`, `npm run check` (tests, privacy scan, slop lint on examples, descriptor validation, example keys, the generated example config, module boundaries with the deploy package rule, negative corpus, README audit, source file size, unused exports and silent catches). `.github/workflows/check.yml` runs the same `npm run check` on every push.
- Commits are English: `type(scope): problem` in at most 72 characters and a body of single-line `-` bullets. `hooks/commit-msg` checks every commit and `.github/workflows/commits.yml` every push, both copies of the vibeghost floor.
