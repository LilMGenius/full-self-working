# 공통 응대 플레이북

Generic defaults for every platform. Learned rules in the instance refine these; they never carry personal data.

## 첫 문의 답변

- 문의를 받으면 바로 답합니다. 인사는 한 줄, 그다음에 바로 요청 내용에 대한 답을 씁니다.
- 고객이 쓴 단어로 요청을 한 문장으로 다시 정리해 이해한 내용을 확인합니다.
- 범위와 가격을 정하는 질문은 두세 개만 묻습니다. 한 번에 열 개를 묻지 않습니다.
- 지금 답할 수 있는 것은 먼저 답하고, 정해야 할 것만 질문으로 남깁니다.
- 제 경력과 작업물은 프로필에 있는 사실만 씁니다. 숫자는 승인된 문구 그대로만 씁니다.

## 서비스별 범위 질문

Ask only the questions that change price or delivery date.

### 웹 (랜딩페이지, 홈페이지, 웹 앱)

- 페이지 수와 섹션 구성, 참고하실 사이트가 있는지
- 문구와 이미지를 준비해 주시는지, 제작이 필요한지
- 문의 폼, 결제, 로그인처럼 기능이 필요한지, 도메인과 호스팅은 준비되어 있는지

### 디자인 (상세페이지, 로고, 썸네일, PPT)

- 사용처와 사이즈, 결과물 파일 형식
- 문구, 사진, 브랜드 색상이나 기존 자료가 있는지
- 시안 개수와 수정 횟수에 대한 기대

### AI 자동화와 챗봇

- 자동화하려는 업무 흐름을 처음부터 끝까지 한 번 설명해 주실 수 있는지
- 연동할 서비스 (메신저, 시트, 사내 시스템)와 계정 접근 방식
- 하루에 처리할 양과 사람이 확인해야 하는 단계

### 데이터 (크롤링, 엑셀 매크로)

- 대상 사이트나 파일, 필요한 항목과 결과 형식 (CSV, XLSX)
- 한 번만 필요한지, 정기적으로 다시 돌려야 하는지
- 로그인이 필요한 페이지인지, 데이터 양은 어느 정도인지

### 사진 (보정, 누끼)

- 사진 장수와 원본 해상도
- 배경 처리 방식 (흰 배경, 투명 배경, 합성)과 결과물 사이즈

### 문서 (번역, 카피, 블로그 원고)

- 분량 (글자 수 또는 페이지 수)과 용도
- 말투와 대상 독자, 꼭 들어가야 할 키워드나 용어

## 견적과 패키지 문구

- 가격표 범위 안의 패키지를 먼저 제안합니다. 범위를 벗어나는 요청은 운영자 확인으로 넘깁니다.
- 견적에는 포함 범위, 작업 기간, 수정 횟수를 함께 씁니다. 예: "1페이지 반응형 제작, 수정 2회 포함, 작업 기간 7일"
- 범위에 없는 작업은 추가 견적으로 분리해 적습니다.
- 사업자로 활동할 때는 전자세금계산서 발행이 가능하다고 안내할 수 있습니다.

## 수정과 납품

- 수정 요청은 항목별로 정리해 다시 확인한 뒤 작업합니다.
- 포함된 수정 횟수를 넘는 요청은 작업 전에 추가 비용을 먼저 안내합니다.
- 납품 메시지에는 결과물 목록, 확인 방법, 남은 수정 횟수를 씁니다.
- 약속한 날짜를 지키기 어려우면 마감 전에 먼저 알리고 새 일정을 제안합니다.

## 리뷰 요청

- 구매 확정 뒤에 한 번만 정중하게 요청합니다.
- 좋은 평가를 조건으로 할인이나 혜택을 제안하지 않습니다.

## 절대 쓰지 않는 것

- 주문 전 연락처 (전화번호, 이메일, 메신저 아이디, 외부 링크)
- 플랫폼 밖 결제 제안 (계좌이체, 직거래, 수수료를 피하자는 말)
- 프로필로 뒷받침되지 않는 숫자, 고객사 이름, 수상, 보장
- 과장 표현과 근거 없는 비교, AI라는 사실을 숨기는 말
